# 2026-05-10 — Pipeline-validation retrain

End-to-end exercise of the cleaned-up trainer + exporter + verification
chain on a fresh checkout. Both networks retrained from the active
corpora; results compared against the artefacts currently in
/mldata/config/track/trackers/.

## Run

    # state head
    python -m bench.train_state_head_decoupled \
        --train bench/data/state_corpus_v18_train.npz \
        --val   bench/data/state_corpus_v18_val.npz \
        --save  bench/data/state_head_dc_v15.pt --epochs 8 --seed 0

    python -m bench.export_decoupled_head \
        --in bench/data/state_head_dc_v15.pt \
        --out bench/data/state_head_dc_v15.bin

    # match cost
    python -m bench.train_phase3 --epochs 25 --seed 0 \
        --save bench/data/phase3_v10_face.pt

    python -m bench.export_phase3 \
        --in bench/data/phase3_v10_face.pt \
        --out bench/data/phase3_v10_face.bin

Both .pt files contain ``ckpt['_meta']`` with full provenance (argv, git
rev, host, UTC timestamp, hyperparams, dataset). Both .bin files end
with a ``META`` trailer (verified by ``python -m bench._artefact_meta
--read``); their `.meta.json` sidecar is also present.

## State-head v15 vs shipped v14 (offline, decoupled-eval)

| Metric                    | v14 (shipped) | v15 (this retrain) | Δ        |
|---------------------------|---------------|--------------------|----------|
| Train wall-clock          | —             | ~90 s              |          |
| Best score (LLR-AUC + life-MAE) | —       | 0.7164             |          |
| TP coverage (TRACKED %)   | 21.66 %       | 28.67 %            | +7.01 pp |
| FP exposure  (TRACKED %)  |  0.57 %       |  1.82 %            | +1.25 pp |
| mota_proxy                | 0.4811        | 0.6153             | +0.1342  |
| fp_per_frame              | 0.0044        | 0.0155             | +0.0111  |
| **fitness_proxy**         | **0.4416**    | **0.4268**         | -0.0148  |
| Trace library (6 traces)  | 7 / 14 pass   | 10 / 14 pass       | +3       |

v15 is the more aggressive head: higher mota / TP coverage but more
FP-tracks, so it loses on the 5e-4 ⋅ fp_tracks penalty. v14 was tuned
for the exact fitness target. v15 wins on trace-library interpretability
(fewer dropped invariants).

**Decision**: keep v14 in production. v15 ships in `bench/data/` as a
validation artefact and a starting point for further tuning (the gain
on trace-lib is the biggest single-recipe move we've seen).

## Match-cost v10 vs shipped v9

Same architecture (TwoTower with face/subbox features auto-detected
from the corpus dtype: obs_in=16, pair_in=19, e_dim=16, tower_hidden=24,
head 32→16→1).

| Metric                        | v9 (shipped) | v10 (this retrain)   |
|-------------------------------|--------------|----------------------|
| Aggregator                    | ema_fixed    | ema_fixed            |
| Train wall-clock              | —            | ~3 min (25 epochs)   |
| Recorded val AUC              | 0.9950 *     | 0.9742               |
| Baseline (no NN) val AUC      | —            | 0.9650               |
| Δ over baseline               | —            | +0.0092              |

\* The 0.995 number comes from `phase3_v9_face.pt`'s ``best_va_auc``
field which used a different validation split (the older
`pairs_val_v9face.npz`, archived). On the current
`bench/data/pairs_val.npz` corpus, v10's 0.974 is the meaningful
number — re-evaluating v9 on this corpus would be required for a true
head-to-head.

**Decision**: keep nn_match_v9_face.bin in production until we have a
proper apples-to-apples bench across both heads on the same corpus.
v10 ships in `bench/data/` as a validation artefact.

## What this run validated

- ✅ Trainers run cleanly from scratch on the current corpora.
- ✅ `--save` is required so produced models can't be silently lost.
- ✅ Face-feature auto-detect on match-cost trainer prevents the
  "trained an obs_in=13 model on an obs_in=16 corpus" footgun.
- ✅ Metadata (argv / git / hyperparams / dataset) lands in both .pt
  and .bin trailer, retrievable via `bench._artefact_meta --read`.
- ✅ Re-export of v14 .pt is bit-identical to the shipped .bin
  (excluding trailer).
- ✅ ubon_cstuff library builds — CMake cu13/cuda_runtime include
  filter unblocks the conda env's CUDA13 header conflict.
- ✅ `unit_tests`: 200 / 200 PASS (after fixing
  MissedFrames_TrackGoesLost to match the runtime's actual emission
  contract).
