# State-head retrain — comprehensive plan

Goal: produce a state head whose training distribution matches what the
runtime actually queries, then redo the experiments that were polluted by
the mismatch.

Context: the existing `nn_state_v5.bin` regresses 68 of 72 PP22 clips that
have both metrics (mean MOTA delta −0.105 vs no-NN baseline). Root cause:
the corpus generated by `bench/build_state_corpus.py` produces a
distribution strictly narrower than what the C runtime queries the head
on. Specifically, four state transitions in the corpus replay disagree
with `ubon_cstuff/src/track/utrack/utrack.c`, plus `e_track` is always
zero in training but non-zero at inference. See "Phase 1" below for the
full list.

## Phase 1 — Make the corpus match runtime (the critical phase)

This is where the bugs we found get fixed. Order within the phase:

### 1a. Audit each transition, ratify or fix

| Transition (state, action)            | Corpus today                | Runtime with NN                     | Fix                                   |
|---------------------------------------|-----------------------------|-------------------------------------|---------------------------------------|
| UNCONFIRMED + matched                 | `obs >= K_min` → TRACKED    | NN decides at every obs             | label-driven oracle                   |
| UNCONFIRMED + not matched             | always REMOVE               | drop_unc head can keep alive        | label-driven oracle                   |
| TRACKED + not matched                 | `missed >= 2` → LOST        | demote head can fire at `missed=1`  | label-driven oracle, `missed≥2` floor |
| LOST + not matched + in window        | stay LOST                   | drop_lost head can drop early       | label-driven oracle, time/miss floor  |
| Track creation, `conf > 0.93`         | always UNCONFIRMED          | TRACKED via `immediate_confirm_thr` | replicate the shortcut in corpus      |
| `e_track` in features                 | always zeros                | non-zero at runtime                 | force `e_track=0` at runtime too      |

The hard floors stay because they exist in the runtime as ceilings — the
head cannot legally override them, so the corpus must not create
transitions that violate them.

### 1b. Implement label-driven replay

- Pre-pass computes `track_gt_history`, `future_alignment`,
  `historic_gt_id` once.
- Replay pass uses **labels** as oracle for transitions, **hard floors**
  as safety ceiling.
- Single shared label code path between replay and label generation —
  no risk of drift between "what state the example was in" and "what
  label it got."

### 1c. Inference-side fix

- `utrack.c`: zero `e_track` at the call site to
  `utrack_build_state_features` for both promote and drop call sites.
  One line per site.
- Document why ("training-time `e_track` was always zero; revisit when
  match-cost NN training is also fixed in Phase 4").
- Rebuild ubon_cstuff.

### 1d. Data inputs

- Confirm pair-trace generation has run on PP22 sequences with
  `debug_match_cost_trace=true`. If not, run it.
- Add PP22 sequences to gt-config for corpus generation
  (`bench/pair_log_config_v7.yaml`).
- Keep MOT and CEVO at their current splits so deltas to v5 are
  interpretable.

### 1e. Bin coverage check

Before training, dump

```
bin (prior_state × bucketed_obs × matched × bucketed_missed) → count, sum_weight
```

- Floor: every (`prior_state`, `matched`, `obs ∈ {1, 2, 3, 4-6, 7+}`)
  bin has ≥100 weighted examples.
- If anything falls short, that's a signal we need augmentation
  (Phase 1f).

### 1f. Augmentation — only if 1e fails

- Per real track, sample up to `M=3` fake starts at offsets
  `[1, 2, ..., K_min+2]`, weight `exp(-offset/τ)` with `τ ≈ 2`.
- Force `prev_det_conf=0, e_track=0, num_missed=0, observations=1` at
  synthetic start; propagate normally.
- Cap per-track total weight at 50 (long tracks shouldn't dominate).
- Add `weight` field to `EXAMPLE_DTYPE`; trainer uses sample weights in
  BCE.

Note: fake starts under-represent genuinely-hard real-first-frame cases
(edge-of-frame entry, partial occlusion, marginal detector confidence).
The decay weighting reflects that — offset=k examples are progressively
less representative of real obs=1 distribution.

### 1g. Train + export

- Use existing `bench/train_state_head.py` with sample weights wired
  through.
- Two operating-point variants exported:
  - `state_v6_aggressive`: lower drop, easier promote — for
    FN-sensitive clips
  - `state_v6_conservative`: current cost ratios

### 1h. Phase 1 benchmark

- Per-clip MOTA matrix vs Phase 0 baseline.
- **Pass criterion**: PP22 mean MOTA delta `≥ 0` vs no-NN baseline
  (currently −0.105). MOT and CEVO no worse than current state-v5.
- **Stretch**: PP22 mean MOTA delta `≥ +0.02` (improvement, not just
  parity).

If we don't pass, this is where we stop and dig in — the issue is
deeper than training distribution.

## Phase 2 — Re-do experiments polluted by the bug

Each of these was previously concluded "didn't help" but the head was
broken. Worth re-running only after Phase 1 lands.

### 2a. e_track re-evaluation

- Generate Phase 1 corpus AGAIN, but with match-cost NN on
  (`nn_path` set, `nn_lambda=0.25` — matches uc_v11). This makes
  `e_track` non-zero in training.
- Train head with non-zero `e_track`, compare vs Phase 1 head on
  per-clip metrics.
- Decision tree:
  - If `e_track`-on beats `e_track`-off by `≥ 0.005` mean MOTA:
    keep `e_track`.
  - Otherwise drop the 16 dims and shrink the head (32→16 input dim,
    one less linear layer width).
- ~1 day.

### 2b. State-head architecture sweep

- The current head is `32 → hidden → e_dim` with single hidden layer.
  Past sweeps were on the broken corpus.
- Try: `hidden ∈ {32, 64, 128}`, `e_dim ∈ {16, 32}`, with/without dropout.
- Validate on per-clip metrics, not just BCE (BCE was misleading on
  the broken corpus).

### 2c. Operating-point calibration

- The 0.5-baked-in threshold is one operating point along a Pareto
  frontier of (FP-track, ID-switch, missed) costs.
- Sweep promote / drop / demote thresholds on the val split, plot
  Pareto frontier per dataset family.
- Pick one operating point per dataset domain if domain-aware
  deployment makes sense; otherwise one global.

### 2d. Match-cost NN audit

Same kind of audit but on the OTHER NN. Almost certain to have similar
issues. Plan within this sub-task:

- Read `bench/build_pair_corpus.py` (or whatever feeds match-cost NN
  training).
- Cross-check every replay rule vs `match_cost.c`.
- If similar mismatches exist, fix them via the same approach
  (label-driven replay + per-track cap + weight decay augmentation).
- Re-train match-cost NN. The state head from 2a depends on this —
  order matters.

### 2e. State head + match-cost NN joint retrain

After 2d, the `e_track` distribution is itself produced by a fixed
match-cost NN. Redo Phase 1 and 2a once more using that.

## Risks and where this could fail

- **Label noise on PP22**: 5 fps eval × 3 s lookahead = 15 frames.
  PP22 is dense after interpolation, so probably fine, but watch for
  clips where short-lived occlusions create label-flipping.
- **Augmentation over-correcting**: if fake-start examples pull the
  obs=1 distribution too far toward "established mid-frame appearance,"
  real edge-of-frame entries get under-represented again. Mitigation:
  the 1e bin coverage check, plus per-track weight cap.
- **e_track Phase 2a may reveal e_track is genuinely useless**. That's
  fine — we want to know definitively rather than guess.
- **Multi-stage retraining (Phase 2e)** could chase its tail. If
  Phase 2d shows the match-cost NN was clean, skip 2e. The decision is
  data-driven.
- **Threshold calibration (2c) may show uc_v11 already sits at the
  right point**. Then we just confirm and move on.

production. Everything in Phase 2 is "make it as good as possible,"
which is valuable but optional.

### 1b/1c. Refactor + inference fix done

`bench/build_state_corpus.py` now has `extract_sequence_label_driven`
alongside the original `extract_sequence`. Switched on with
`--label-driven`. Adds `--immediate-confirm-thr`, `--delay-aug`, and
`--delay-aug-tau` flags. `EXAMPLE_DTYPE` gained a `weight` field
(default 1.0; set < 1.0 by delay aug).

What the new extractor does differently:
- Pre-computes `track_gt_history` using **both** emitted objects and
  pair-trace track boxes, so UNCONFIRMED/LOST tracks get real GT-id
  records instead of "no GT" by default.
- Replays state with **label-driven oracle transitions**, with hard
  floors (`missed≥2 → LOST`, `time≥buffer or missed≥max → REMOVED`)
  preserved.
- Mirrors `utrack.c:1707` immediate-confirm shortcut: tracks with
  initial `det_conf > immediate_confirm_thr` start as TRACKED.
- Forces `e_track=0` (matches the planned runtime fix).
- Optional delay augmentation: for each track, emit additional
  trajectory copies that hold the track UNCONFIRMED for K extra frames
  before applying the oracle transition. Each copy weight =
  `exp(-K/τ)`.

Smoke test on PP22_00001 (100 frames, 18 tracks):

| variant                 | examples | UNCONFIRMED obs=1 promote_pos | UNCONFIRMED obs=2 promote_pos | UNCONFIRMED obs=3-4 promote_pos |
|-------------------------|---------:|------------------------------:|------------------------------:|--------------------------------:|
| label-driven, no aug    |      425 |                          14 / 16 |                           0 / 2 |                            0 / 4 |
| label-driven, aug=1,2,3 |     1898 |                          59 / 67 |                          45 / 53 |                          39 / 61 |

The no-aug variant has **2 examples total** at UNCONFIRMED obs=2 (both
non-promotable), so the head would learn "obs≥2 UNCONFIRMED → never
promote" — exactly the bug we're trying to fix. Delay augmentation
fills in the obs≥2 promotable region. Adopting `delay-aug=1,2,3` for
the full corpus build.

C runtime fix: `e_track` zeroed at both call sites in `utrack.c`. The
existing buffer is reused (just `memset(0)` before the
`utrack_build_state_features` call) so no struct ABI changes needed.

Next: build full corpus, train, export, benchmark.

### Cost-ratio sweep (v8 → v9 → v10)

v8 was at parity but below no-NN on PP22 (−0.007). The default cost
ratio `cr_promote=0.1` pushes the head to be conservative on
promotion (cFP=10×cFN). For PP22 we want the opposite — promote more
to recover the recall the broken state-v5 was losing.

| variant |  cr_promote | cr_demote | drop_unc | drop_lost | mean MOTA PP22 | Δ vs no-NN PP22 |
|---------|------------:|----------:|---------:|----------:|---------------:|----------------:|
| v8      |         0.1 |       1.0 |      0.2 |       0.1 |          0.394 |        −0.007  |
| **v9**  |     **1.0** |   **1.0** |      0.2 |       0.1 |      **0.401** |    **+0.0004** |
| v10     |         2.0 |       0.5 |      0.2 |       0.1 |          0.395 |        −0.006  |

v9 with balanced promote (cr_promote=1.0) is the winner. Pushing
further (v10) hurts because the head starts promoting marginal tracks
too eagerly, costing precision. v9 ≥ no-NN on **40/95** PP22 test
clips, ≥ v8 on **69/95**.

Threshold tuning at export time (promote_thr 0.9 → 0.5) made
**zero** difference — the head's logits are saturated (val AUC =
0.998) so the threshold doesn't separate cases. Cost ratios at
training time matter; thresholds at export time do not (in this
regime).
